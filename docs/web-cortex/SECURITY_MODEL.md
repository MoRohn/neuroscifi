# Web Cortex: security model

Status: describes the working tree on top of `64da95b`, including the UAT fixes not yet committed. Controls are mapped to code and to the test that verifies them; where no test exists the entry says so. The interface surfaces (CLI, console, Pocket, MCP) are in the code and have their own tests, cited in rows 24 to 26 and section 7; routes and bodies are in API_CONTRACTS §8. Related: [SEARCH_AND_ACQUISITION.md](SEARCH_AND_ACQUISITION.md), [EVIDENCE_AND_PROVENANCE.md](EVIDENCE_AND_PROVENANCE.md), [MEMORY_INTEGRATION.md](MEMORY_INTEGRATION.md), [DEPENDENCY_REVIEW.md](DEPENDENCY_REVIEW.md). ## 1. Scope and assumptions

Web Cortex gives one individual's NeuroSciFi instance a governed path to the **public** web. Until 0.6 nothing in the project contacted a network service (ADR-021). The security question is what that path adds to the attack surface and what leaves the machine through it.

Assumptions:

- The host is single-owner and runs the service as an unprivileged user. The state directory is on an encrypted volume (ADR-011).
- Everything that arrives from the network is hostile until measured: search results, page text, titles, metadata, feeds, PDFs, API fields, `robots.txt`.
- The package contains no model that could be instructed (ADR-022). Injection harms the pipeline's *data* (poisoned claims, wasted budget, leaked queries), not an agent's actions. A downstream agent that reads reports or MCP output must still treat them as data.
- TLS trust, DNS and the operating system's resolver are those of the host.

Not in scope: private networks, authenticated sites, paywalls, the owner's own files. None of these is fetched.

## 2. Assets and adversaries

| Asset | Why it matters |
|---|---|
| Private memory (evidence journal, beliefs, partner and camera roots, objectives) | Must not leave in a query or log |
| Individual's knowledge base | Must not be poisoned silently |
| Local network and host (loopback services, LAN, metadata endpoints) | Must not be reachable through the fetcher or browser |
| CPU, memory, bandwidth, request quota | Must be bounded per task and per day |
| Third-party sites | Must not be harmed or deceived by the crawler |

| Adversary | Capability |
|---|---|
| Malicious website or search result | Chooses content, redirects, DNS answers, headers, response timing |
| Compromised or noisy search engine or API | Returns false or hostile records |
| Network observer | Sees destination hosts and timing (TLS hides paths and content) |
| Paired Pocket device on the LAN | Holds a bearer token; can reach the Pocket bridge |
| Other local user or process | Can reach loopback ports and read files the OS allows |

## 4. Privacy

**What may leave the machine.** Only what the owner's objective yields after screening: keyword queries to the loopback daemon (which forwards them to the search engines) and to the structured APIs, and the URLs fetched. Destination hosts and timing are visible to the network and, for DNS, to the host's resolver. Engines and APIs see the query text and the host's IP address; the project cannot prevent that. A *public* term in a query still reveals interest in that topic.

**Screen** (`safety.privacy_screen`). Detects: e-mail addresses; phone numbers (9-15 digits **with phone formatting or a phone word before them**: an international prefix, an area code in parentheses, three or more digit groups that are not thousands grouping, a trunk-prefix pair such as "07700 900123", or "phone", "tel", "call", "mobile" and similar just before the number; bare digit runs such as 299792458, decimals, arXiv ids, year ranges and ISBNs are not phones: `test_phone_needs_phone_formatting_or_context`, `test_phone_positives_with_formatting_or_context`); IPv4 and IPv6 literals (an IPv4 right after "version", "release" or "v" is a version, not an address); MAC addresses; absolute file paths (`/home/...`, `~/...`, `C:\...`); API-key prefixes (`sk-`, `ghp_`, `AKIA`, `xox*-`, `AIza`, ...); Luhn-valid card numbers; long mixed-case or base64-like secrets of at least 24 characters; and **private terms** (whole word, case-insensitive). Findings carry the kind and a masked excerpt, so they can be logged safely (`test_privacy_excerpts_never_echo_the_secret`). An empty list is the only "safe to send" signal.

**Private terms** are the owner's `private_terms` plus every root of the evidence journal on the `camera` and `word` (partner) channels, read at screening time (`orchestrator.private_terms`). Erased roots leave the journal and so leave the list; erasure rewrites their mentions to salted digests (ADR-019).

**Where the screen runs.** On the objective at `submit`: a finding rejects the task, and the error names the kinds, not the text. On every planned query: a finding drops that query and logs the count and kinds (`decision` event). On monitor topics. Monitors and curiosity build queries from public claim text only.

**Self-references stay local.** Before queries are built, `intent.strip_local` removes references to the individual's own system: `NeuroSciFi` and its spelling variants (`intent.SELF_NAMES`), "our", "my", "this individual", "the libraries we use", and the owner's `private_terms`, with the noun phrase a possessive owns. Such text is answered from local documents and state and never reaches a search engine; the plan's `notes` says how many references were withheld (`test_self_references_are_local_context_not_web_queries`, `test_plan_and_refine_never_search_the_individuals_own_system`). Stripping is lexical: a local name that is neither in `SELF_NAMES` nor in `private_terms` is not recognised.

**Owner-approved disclosure is per task and narrow.** `submit(..., authorization="owner-approved-disclosure")` stores an objective that contains private data and lets **that task's own** planned queries carry exactly the private text the objective contained (a query is kept only when every finding in it is text found in the objective). Each disclosure is a `decision` event `disclosed_under_authorization` with the count and finding kinds, never the text. The authorisation is refused (`ValidationError`) for curiosity and refresh tasks and for a monitor the owner did not authorise; it does not extend to other tasks or to any private text the owner did not write into the objective; `requeue` carries it to the child task. Without it a private term never leaves in a query (`test_owner_authorisation_applies_to_the_tasks_own_queries`). This resolves the earlier divergence from ARCHITECTURE §3, which says the screen can be passed by explicit authorization.

**Storage.** Objectives, queries (as events), claims and knowledge live in the individual's file under its protections (mode 0600, volume encryption). The public cache holds public bytes keyed by URL and content hash, no queries, no objectives, no claims, and is excluded from checkpoints (ADR-023). `purpose="api"` responses are never cached.

**Not stored.** Cookies; response bodies in logs; query strings in error messages; the host's name (only a 12-character SHA-256 digest in `executed_on`).

## 5. Responsible acquisition

| Practice | How it is enforced |
|---|---|
| `robots.txt` always on | Constant, not a setting (`config.RESPECT_ROBOTS`). Applies to `page`, `feed`, `crawl` and browser sub-requests (`purpose="subresource"`); documented public APIs (`purpose="api"`) are exempt. Rules are matched per RFC 9309 (`net.RobotsRules`). Failure semantics in SEARCH_AND_ACQUISITION §6: a 5xx or an unreachable `robots.txt` blocks the host |
| Identifiable agent | `NeuroSciFi-WebCortex/0.7 (research agent; honours robots.txt)`. No browser impersonation, no header forging. No contact address is sent, which protects the owner's identity but gives site operators no way to reach the owner |
| Rate limits | Default 1 request per second per host (up to 3600 s configurable); the effective gap is the largest of that, the per-host interval (`NetPolicy.host_intervals`: `export.arxiv.org` 3.0 s as arXiv asks, `eutils.ncbi.nlm.nih.gov` 0.34 s as NCBI asks without a key) and `Crawl-delay` (up to 60 s); browser sub-requests use 0.1 s and not `Crawl-delay`. `Retry-After` honoured up to 6 h, 429 backs the host off, and the backoff is shared through the public cache (`test_host_intervals_with_fake_clock`, `test_retry_after_shared_by_fetchers_on_one_cache`) |
| No anti-bot circumvention | No Cloudflare or CAPTCHA solving, no TLS fingerprint spoofing, no proxy rotation. `scrapling[fetchers]` is deliberately not installed (ADR-024, DEPENDENCY_REVIEW §2). Blocked pages are reported unavailable |
| No authentication or paywall bypass | No credentials are sent; no login flow exists; `Authorization` is never set by this code |
| Bounded use | Task budgets, daily autonomous caps, page and byte limits; the crawler follows at most 2 same-site links per task. Pages fetched ahead of their turn (`read_ahead`) share the task's budget: together they send no request and read no byte the task has no room for (charged, sent unused before, held in flight), so unused read-ahead traffic never exceeds the budget itself; tasks under a daily cap fetch nothing ahead, and the caps count unused read-ahead traffic (`scheduler.traffic`). A fetch ahead never opens a second connection to a site an exchange is in progress with |
| The owner's stop is immediate | Cancel, web access off and a denied domain are read before every name lookup, before every connection and again before every request of a page fetch, a crawl's sitemaps included (`SafeFetcher.gated`, `speculate(wanted=...)`): no request is sent afterwards; a connection being opened may complete its handshake with nothing sent on it. Requests already on the wire are cut within 0.25 s (`tests/webcortex/test_read_ahead_stops.py`). Searches notice within 2 s, at their next round |
| Attribution | Every claim keeps its source URL, domain, dates and content hash; reports cite every statement; quotes are single sentences, not whole pages |

The search daemon scrapes public engine result pages. Whether that is acceptable under an engine's terms is the owner's decision; the daemon's own behaviour is outside this project's control (DEPENDENCY_REVIEW §3).

## 6. Read-only defaults and separation of privileged tools

- **Default state is off.** `enabled`, `autonomous`, `pocket_research` and `browser_rendering` are all false (`config.WebConfig`); every network entry point calls `state.require_enabled`. A fresh individual behaves exactly as 0.5. `news_rendering` is true (ADR-041) but has no effect until the owner enables web access; it then lets a news question a person asked render at most one scripted news page per task (40 per day) in the sandbox above.
- **The web path is read-only toward the world.** Only GET and HEAD, plus POST for documented read APIs (OSV). Nothing posts forms, submits data or acts on a site.
- **Web content never reaches privileged operations.** Configuration (`state.set_config`), forgetting (`governance.*`), acceptance (`knowledge.apply_review` through `nsf resolve`) and monitor authorisation are owner actions on separate code paths. No function in `webcortex` takes content as a command.
- **MCP.** `nsf web mcp` is a stdio server with read-mostly tools `web_search`, `web_research`, `web_task`, `web_evidence`, `web_knowledge`, all content wrapped in `safety.untrusted()` envelopes, and **no forget, review, config or monitor tool**: `test_handshake_listing_and_protocol_errors` asserts the exact tool list and that no tool name contains those words, and that an unknown tool (`web_forget`) is an error. Other tests: `test_research_task_evidence_and_knowledge_are_wrapped_as_untrusted`, `test_privacy_screen_applies`, `test_tools_refuse_while_disabled_and_validate_inputs`, `test_spawned_server_round_trip` (`tests/webcortex/test_mcp.py`). `safety.untrusted` and `synthesis.context_pack` (envelopes) are tested (`test_untrusted_envelope`, `test_context_pack_respects_token_bound_and_wraps_untrusted`). An MCP client that treats the output as instructions is outside this control.
- **Autonomy is capped and scoped.** Refresh and curiosity research only touch items already in knowledge or owner monitors, within `daily_autonomous`; new topics are proposals the owner must confirm (MEMORY_INTEGRATION §7-8).

## 7. Surfaces

| Surface | Exposure | Control |
|---|---|---|
| Console | Loopback only, bearer session token (ADR-013) | Owner-only; `/api/web/*` may change only the four switches; token, Host, Origin and body-size rules apply to every route; research runs in `neuroscifi-webcortex.service`, not in the console process (the embedded worker is opt-in with `--web-worker`; leases prevent double execution). Tests: `tests/console/test_console_web.py`, `tests/e2e/test_console_research.py` (row 26) |
| Pocket bridge | LAN or VPN, TLS required off loopback, bearer and pairing (ADR-028) | Research off by default; four actions (`research_submit` up to 300 characters in a body of at most 1024 bytes, `research_list`, `research_get`, `research_cancel`) scoped to the device's family; a family holds at most 6 devices; `nsf pocket erase-pairing LABEL --family` or "Forget all linked devices" (`unpair` with `{"family": true}`) revokes the whole family; connection limits as row 27; cannot accept knowledge, change configuration or forget; no Pocket route creates a monitor. Tests: `tests/test_pocket_research.py` (row 24) |

| Public cache file | Same directory as the individual file | Mode 0600, under the 0700 state directory |

## 8. Encryption at rest and retention

- **Encryption at rest** is delegated to the volume (ADR-011): files are 0600 in a 0700 state directory and an encrypted volume is a deployment precondition. Web Cortex adds no application-level encryption; the public cache is likewise on that volume. `nsf doctor` reports the filesystem type but cannot prove encryption.
- **Public cache retention.** Bounded by size (`cache_max_bytes`, 512 MiB) and age (`cache_max_age_days`, 30) through `PublicCache.prune` (oldest first); `secure_delete` is on and the WAL is truncated after pruning and forgetting (`test_prune_by_age_and_size_lru`, `test_forget_url_and_domain`). Retention is wired: `Services.prune_cache` runs `PublicCache.maybe_prune` (at most hourly) at the end of every research run and every scheduler tick, and `nsf web cache prune` runs it at once (`test_maybe_prune_runs_at_most_once_per_interval`, `test_tick_and_runs_apply_cache_retention`). Forgetting a body drops it only when no other URL row references it (`test_forget_deletes_only_orphaned_bodies`).
- **Task, claim, knowledge retention** is "until forgotten" (visible in `memory.retrieve` permissions). There is no automatic expiry; the owner forgets by task, source or knowledge item (MEMORY_INTEGRATION §6).
- **Checkpoints** exclude the public cache; forgetting marks existing checkpoints stale.

## 9. Accepted and residual risks

Accepted, with reasons:

| Risk | Why accepted |
|---|---|
| `zod < 4.6.6` advisory (GHSA-mrhx-c7xc-m3w5) reachable through open-webSearch | The daemon binds 127.0.0.1; its only client sends bounded requests (query 512 characters, limit 20, fixed engines). Revisit when upstream moves to a fixed `zod`. DEPENDENCY_REVIEW §3 |
| Regex-based injection detection | It is a filter, not a proof. English, imperative, agent-directed phrasing only; paraphrase, other languages and instructions split across sentences can pass. The defence in depth is that content has no path to act (control 12) and flagged or unflagged claims still need independent agreement and owner acceptance |
| Text hidden by stylesheet rules is kept | The cleaner understands inline styles, `hidden`, `aria-hidden`, templates and common hiding class names. Text hidden by an external or `<style>` rule with arbitrary class names looks visible to it. The rendering path does not change that |
| Coalesced requests share one result | Identical concurrent GETs get the leader's response; only the leader's budget is charged, so a follower task is not charged for the request it used, and it inherits the leader's failure |
| Per-process throttle slots | Two processes (worker and a manual fetch) can together exceed the per-host interval, because request slots are not shared. Retry-After backoff and robots entries are shared through the public cache |
| `robots.txt` 401/403 treated as "no file" | Any 4xx allows the host. This follows the common reading of RFC 9309 for unavailable files but is permissive |
| Unofficial engine scrapers | Reliability and terms-of-service exposure are the daemon's (DEPENDENCY_REVIEW §3) |

Residual, not mitigated by code:

- **Extraction CPU is only partly bounded.** The 15 s limit covers the network read. HTML extraction is bounded by element, Markdown and text caps (control 9); a crafted PDF (30 pages, 500,000 characters) and the claim extractor over a 500,000-character text can still cost seconds. Budgets bound the number of documents, not the work per document.
- **Chromium vulnerabilities.** The sandbox is on. General rendering is off by default; news rendering (ADR-041) is on by default for a person's news questions, so with web access enabled Chromium does run untrusted news-site JavaScript by default (at most 1 render per task, 40 per day; `nsf web config --no-news-render` turns it off). A renderer exploit would run as the service user. The service units carry systemd hardening directives (`deploy/systemd/neuroscifi-webcortex.service`: `NoNewPrivileges`, `ProtectSystem=strict`, `SystemCallFilter`, `MemoryMax=2G`); no test in this repository verifies them.
- **Traffic analysis.** Hosts contacted, timing and query text to engines are visible to those parties.
- **Cache not purged by every forgetting path.** `forget_research` leaves public page bodies in the cache (the same page may serve other tasks), and `governance.forget_source` only names the cache keys. `nsf forget source` then drops them through `PublicCache.forget_url` or `forget_domain`; a caller of the governance function alone, and a forgotten task's pages, stay until retention prunes them (30 days or 512 MiB by default). They hold no queries or objectives.
- **Third-party text is stored** (sentence-level quotes in claims, up to 5 MB bodies in the cache). Copyright and retention of that text are the owner's responsibility; forgetting removes it.
- **Pocket compromise** lets an attacker spend the owner's request budget (at most 10 submissions per hour for the family) and read that family's reports, not other families' tasks or the private memory. One lost device does not revoke its family's other devices: `nsf pocket erase-pairing LABEL` removes one device, with `--family` the whole family.
- **Pocket connection limits are not authentication.** The 32/8 connection caps and 10 s deadline keep slow clients from holding every slot; a determined LAN host can still occupy its own 8 slots and delay, but not block, other addresses.
- **Local processes** can query the loopback daemon and, if the OS allows, read files in the state directory.
