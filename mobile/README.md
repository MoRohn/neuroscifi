# NeuroSciFi Pocket

Pocket is the phone interface to one NeuroSciFi instance. Its field workspace runs on a phone or tablet and can learn from outcome-labelled episodes offline. The included browser client also samples the microphone for relative sound level, samples the camera for one brightness category, and accepts four self-reported activities. It serves its own static assets and calls only its paired bridge. The bridge's per-pairing predictor feeds the history screen. The main connectome's binary calibration inputs have different semantics; Pocket observations do not silently update those circuits.

## Try it on one computer

From the NeuroSciFi project root, run:

~~~sh
nsf pocket serve --db mobile-private.sqlite
~~~

Open http://localhost:8765 on that same computer. Sensors begin off. Try **Check sound** or **Mark an activity** before pairing. Copy the one-use code from the terminal to pair, then share a reviewed item. Select the learning checkbox if you want it included in the prediction. Use **Forget** on the item and refresh to see the estimate change. A terminal pairing starts a separate history. A handoff from a paired device joins its field episode group. Pairing requires the Spark process to be reachable.

## Connect an actual phone

Use a private LAN or a private VPN between the phone and Spark. Supply a TLS certificate for the hostname you will enter on the phone, its matching private key, and a certificate chain trusted by that phone. On the Spark, bind to its private interface. Substitute your actual values below:

~~~sh
nsf pocket serve --bind PRIVATE_INTERFACE_IP --port 8765 --cert /path/to/fullchain.pem --key /path/to/privkey.pem --db /path/on/encrypted-volume/mobile.sqlite
~~~

Open https://YOUR_CERTIFICATE_HOSTNAME:8765 on the phone and enter the terminal code within five minutes. One running server issues one invitation at startup. To issue another, restart the bridge against the same DB. The phone keeps its pairing credential in tab memory. Reloading loses the default in-memory credential. To resume, explicitly select “Keep pairing in this vault for 24 hours” while paired. Restoring a pairing from the vault checks it with the Spark first; the header says **Checking your Spark…** until it answers, and a refused pairing is dropped from the vault. **Forget this pairing** also removes the vault's copy. Server-side revocation is independent. On the Spark, list pairings and erase abandoned ones using the commands below. Use a private OS account, encrypted data volume, and exclude the bridge database from backups and cloud sync. The prototype stores SQLite in cleartext within that volume. It does not configure the network, certificates or encryption for you.

~~~sh
nsf pocket list-pairings --db /path/on/encrypted-volume/mobile.sqlite
nsf pocket erase-pairing LABEL --db /path/on/encrypted-volume/mobile.sqlite
nsf pocket erase-pairing LABEL --family --db /path/on/encrypted-volume/mobile.sqlite
~~~

`list-pairings` prints one line per device: its random label, `family=` (a short tag shared by a device and every phone or tablet linked from it), `sponsor=` (`invitation` for a device paired with the terminal code, else the label of the device that issued its handoff code) and `created=` (UTC; `unknown` for pairings made before this field existed). `--family` erases the label's whole family. A family holds at most 6 devices: **Link my phone or tablet** refuses to issue a code for a full family, and a code issued before it filled up is refused at pairing.

With `--invitation-file`, the code goes to a new 0600 file. After a crash the file can remain; the next start replaces it only when it is a regular 0600 file owned by the bridge's user (never a symlink) holding one code, and either no running bridge holds its lock or the code has expired (older than 5 minutes). Anything else stops the start with an error, and the file is left as it was. A busy port is reported in one line (`nsf: cannot listen on ADDRESS:PORT: Address already in use`).

**Connection limits.** The bridge serves at most 32 connections at once and 8 from one address. Each connection must deliver its whole request (TLS handshake, head and body) within 10 seconds of being accepted; slower ones are closed. When all 32 slots are taken, or its address already holds 8, a new connection closes the oldest one still waiting for its request (one that has not finished its TLS handshake first; from its own address in the second case), so slow or silent clients cannot lock phones out.

## Controls and data contract

- **Sound.** A 1.5-second sampling window yields soft, moderate or strong relative to the microphone's digital full scale. Driver processing and route affect the result. Three bins have no calibrated sound-pressure meaning.
- **Light.** One local camera frame is reduced to a single pixel and classified as dim, midrange or bright. Exposure varies by phone. Neither a displayable picture nor a transcript appears in the API.
- **Activity.** Choose focus, walk, rest or other. This is self-report. No GPS, accelerometer or contact permissions are requested.
- **Speak an activity.** On a supporting browser, deliberately start local US English recognition in a private setting. Require an already installed language pack and explicit local-only mode, with no automatic download or cloud fallback. Only a whole utterance matching one of four activity labels becomes a draft. Unsupported speech, including a label followed by a name, is discarded. The user reviews the label as a self-report. The feature does not identify who spoke.
- **Review.** Only the latest local draft survives. You can discard it, save it as memory only, or separately opt it into learning. A hidden page clears the draft. Closing before sharing loses it. Manual Stop ends sensor use and preserves the displayed draft for review.
- **Listening session.** Start up to five minutes in the foreground. Review-only is the default. While the page stays visible a separate, per-session opt-in can send a coarse sound band roughly once per minute and enable learning on those events. This samples the most recent window at that point; it is not a minute-long acoustic average. Stop, hiding the page, input interruption, expiry, or a failed automatic share ends capture. A request already sent may finish. The user can inspect its receipt and forget it. No automatic retry queue. Permission prompts and input acquisition count against the session deadline.
- **Single readings.** A random v4 event ID, channel, one fixed categorical value, and a learning boolean. Unknown fields, arbitrary text and media are rejected. HTTPS and authorization headers carry transport metadata. A receiver necessarily sees a connection address and time. The prototype avoids application access logs. Infrastructure under the operator's control may keep separate logs.
- **Single-reading estimator.** For each channel, each retained opted-in observation adds one count. The predictor uses a uniform Dirichlet prior of one per category. Review the next-observation distribution via state or its highest-probability values in the UI. Selection and placement bias limit interpretation. Deleting or expiring evidence removes its contribution immediately on the next read. No weights are exported.
- **Evening review.** Shows the last time a sensor was active (kept in this tab's memory and never sent), the observation waiting for approval, and the shared observations that are changing the forecast. **Forget this** removes one item. **Forget this session** loops the existing forget calls over the IDs this tab shared since pairing, shows progress, and reports a partial failure with a count instead of hiding it. **Stop learning this pattern** calls `mute` for a channel: its existing observations stop learning, the forecast recomputes, and a new save with learning on that channel returns 423 until **Resume learning** (`unmute`). Muted channels are stored per pairing, hold no observation, and are erased with the pairing. An identical retry of an already stored event still returns 200.
- **Home screen.** `/manifest.webmanifest` and `/icon.svg` let a phone install Pocket with shortcuts to the field session, Mark an activity, and Sense. The manifest also declares the share target described under Research. Both are in the offline shell (nine assets with the Research module, cache `neuroscifi-pocket-shell-8`; the plan counted six before the manifest, icon and Research module). Chromium may want PNG icons before it offers an install prompt; the SVG is the only icon shipped.
- **Expiry.** Records expire 24 hours after receipt. A running server sweeps each minute and before reads/writes, and sweeps at startup. Duplicate delivery never extends expiry. Random ID tombstones remain per pairing to prevent replay; unpairing deletes those IDs and invalidates the credential. SQLite secure deletion is enabled. Backups and storage-device remnants are outside the demonstrated erasure scope.
- **Status and the Spark.** The header shows **Paired with Spark** only while the Spark answers; otherwise **Paired · Spark unreachable**, **Paired · this device is offline**, or, when the Spark no longer accepts the pairing, **Not paired · pair again** (the page then asks for a new code and drops any copy kept in the vault). A wrong, expired or already used code reads "That code was not accepted…", which differs from "Could not reach your Spark…". Messages at the bottom clear themselves after 8 seconds or with **Dismiss**.
- **Offline.** Once the program cache is ready, the field workspace can reopen without the Spark in browsers supporting service workers. Vault persistence also requires Web Crypto, Web Locks, storage, and a passphrase. The browser may evict data. No automatic upload queue or background browser sensing is used. Free-form dialogue and native prolonged listening remain design work.

## Use a field session

1. Before leaving connectivity, open the trusted HTTPS page and wait for **Offline shell ready**. Open a vault with a passphrase of at least 12 characters if you want to leave the page and later submit feedback. Browser origin and port must stay the same. Without a vault, hiding the page clears the session.
2. Choose your goal. Use **Check sound** or **Check sound variation**, then **Include last sound check**. Time Pocket itself, or select a screenshot or a native metrics JSON file. Inspect the source and category for each input. A picker may hide the page and clear an uncommitted draft on some platforms; import first and check the displayed context.
3. Choose **Predict next outcome** before switching tasks. After returning, unlock the vault to restore that pending estimate. Open **Why this estimate?** to inspect its distribution and evidence. Record Continued, Switched tasks or Paused (one tap records one outcome; the area stays in place, so a quick second tap lands on nothing). Choose learning separately. **Forget here** asks for confirmation. Default lifetime is 24 hours, with an optional seven-day grant for an individual completed local episode. The vault holds up to 64 entries including the unfinished prediction. Erasure or expiry can invalidate an unfinished local prediction.
4. **Share episode** sends its fixed features and provenance, UUID, outcome and learning flag. The server stores up to 64 field episodes per originating pairing. A linked-device view returns the most recent 256 in the group. Source tags on imported files are declarations and can be forged. Raw screenshots, audio, URLs, app packages, exact timestamps and sensor time series are outside the API. A reviewed export remains in Files until its owner removes it.
5. Choose **Link my phone or tablet** on a paired device. Enter its temporary code on the other device. Linked devices may read and forget shared field episodes. Enable **Consult linked devices** before a forecast to include current approved Spark episodes. Identical event IDs contribute once. This option needs connectivity, and never silently falls back when requested. Local-only episodes stay in the browser vault. Erase each copy using the corresponding local or Spark control. **Forget all linked devices** erases this device and every device of its family on the Spark. Revoking a pairing on Spark also removes the shared episodes it originated. The locally protected unlock credential has no effect after server revocation.

## Research from Pocket

Off by default. Pocket can queue a research question for your Spark only when both of these hold:

1. The individual has web access and Pocket research on: `nsf web config` with `enabled` and `pocket_research` true (ADR-021, ADR-028).
2. The bridge is started with the individual's database:

~~~sh
nsf pocket serve --db /path/on/encrypted-volume/mobile.sqlite --instance-db /path/on/encrypted-volume/individual.sqlite ...
~~~

If either is missing, the four research actions answer a paired device 404 like unknown routes, and the page shows no Research panel. A caller without a live pairing credential (no bearer, an unknown or revoked one, or a foreign Origin) gets the same empty 403 whether research is on or off, so the LAN cannot learn the setting. Pocket never fetches or researches anything itself. A task is a row in the individual's database (never in the Pocket database, ADR-005). It runs only when the Spark's worker drains the queue (`nsf web work`, or the console's worker). Until then it stays **Queued**.

- **Ask.** Write a question of up to 300 characters (a counter shows the characters and the bytes the request will take, out of 1024). Optionally pick a kind: quick lookup, deep research, check a claim, compare options, scientific literature or technical. Otherwise your Spark chooses (an omitted kind is assessed from the question, as in the console). The bridge refuses questions containing e-mail addresses, phone numbers, network addresses, file paths, secrets, or names the owner marked private (including camera and partner names from the journal). Nothing is queued, and the page asks you to remove them. A pairing family (a device and the devices linked from it) may queue up to 10 questions per hour together. The count is kept in the Pocket database with the family and submission time only, survives a restart of the bridge, and is deleted after an hour or when the family is erased. If the individual's regulation has paused writes (for example low disk space), the bridge answers 507 and the page says that your Spark paused new research.
- **Share a link.** Installed Pocket registers as a share target (`share_target` in the manifest, GET to `/`). Sharing a web page from another app opens Pocket at `/?share_url=…&share_text=…`; the page removes the query from the address bar and history at once and prefills **Summarize: <link>** when the link is http or https, has no user name or password, and the question fits in 300 characters. Android often puts the link in the shared text; the first http(s) link there is used. Nothing is submitted for you: before pairing the Research panel only says to pair, and after pairing you review and press **Submit**. The bridge never reads the query (it serves the same page), and Pocket does not fetch the link: your Spark's worker reads pages named in a question. The service worker never answers a URL with a query from its cache, so sharing needs the Spark to be reachable.
- **Dictate.** The **Dictate** button appears only when the same on-device US English gate as **Speak an activity** passes. Dictation fills the text field for you to review. It never submits.
- **Follow.** While a question is running and the page is visible, the page asks for its status every 3 seconds and shows the stage (Discovering, Reading, Evaluating, Synthesizing, Completed). Hiding the page stops polling, closes the open report and clears the unsent question.
- **Read.** The phone receives a trimmed report: for a claim check, the verdict (supported, disputed, contested or not enough evidence) with its confidence and the claim checked; the answer with quoted sentences and [n] citations, each marked corroborated, single source or contested with its confidence where the Spark computed one, contradictions, uncertainties, limitations, freshness, and sources with publication and retrieval dates, each marked **Live** or **From cache**. All server text is shown as plain text. Source links open only for http and https addresses, with no referrer.
- **Read aloud.** Optional and off until pressed. **Read aloud** speaks only the quoted answer sentences, each followed by "Source n" for its citations (no titles, domains or links), with the browser's speech synthesis. Only a voice the browser marks as on-device (`localService`) is used; with network voices alone nothing is read and the page says so. **Stop reading**, closing the report or hiding the page stops it.
- **Finished while you were away.** Hiding the page stops polling. When the page is shown again, it lists the questions that were running when you left and have finished since. This needs no permission.
- **Notifications.** Off by default, for this visit only; the switch **Notify me when a question finishes** is the only place that asks for notification permission. With permission, the service worker shows "Pocket research finished: Completed. Open Pocket to read it." when a status check of the open page sees a question finish while the page is visible but not focused (beside another window, split screen). The notification never contains the question. What does not work: there is no push service, so a hidden, backgrounded or closed Pocket checks nothing and shows no notification; you get the summary above on return instead. Native background delivery remains design work (POC-25/26).
- **Cancel.** A queued question is cancelled at once. A running one stops before its next network step.
- **Save for offline.** This stores the report in the encrypted device vault (the same AES-GCM vault, passphrase and lock-on-hide as field episodes). It counts toward the vault's 64 entries, with at most 8 saved findings, and expires after 24 hours. Without an open vault nothing is stored. After going offline, reopen the page, unlock the vault and choose **View**. **Erase local vault** removes saved findings too.
- **Linked devices.** A phone or tablet joined through **Link my phone or tablet** belongs to the same pairing family. It sees, reads and can cancel the same questions. An unrelated pairing sees none of them: their ids answer 404 and they are absent from its list. Tasks are stored under an instance-salted digest of the family, never the credential or its fingerprint.
- **Owner.** The console and `nsf web` CLI see every task, whichever device asked. Erasing or unpairing a device does not delete the questions it asked: they belong to the individual, and a linked device of the same family still sees them. The owner removes them with `nsf forget research` (ADR-029) or the console.
- **Limits of the surface.** Pocket can submit, list, read, cancel and save. It cannot accept knowledge, change configuration or forget the individual's memory. Request bodies stay at most 512 bytes under the existing bearer, origin, content-type and TLS rules, except `research_submit`, which may take 1024 bytes. Deviation, with reason: 300 characters of a non-Latin script take up to 900 bytes of UTF-8, which the 512-byte cap refused although the question was within its character limit; the character limit is unchanged. No access logs are written, and the `Server` header names no Python version.

## Native collectors

**Android phones and tablets.** Open `mobile/native/android` in Android Studio with SDK 35 and the Android Gradle Plugin 8.7 compatible toolchain (Gradle 8.9 and JDK 17). Build the app module and run on API 29+. The project includes Gradle build files and uses platform Java APIs. Select system readings, usage readings, or both. Open the system's Usage Access settings to grant the app permission if needed. Optionally enter one designated app package locally. Review and save the categorical JSON, then import it in Pocket. Usage bands cover the preceding hour. App-duration and screen-duration bands count only intervals with observed endpoints; missing boundaries, split-screen and device restarts limit interpretation. The collector has no internet permission. Package identifiers and exact durations stay out of the file.

**iPhone and iPad.** In Xcode create a SwiftUI iOS app targeting iOS/iPadOS 17+ and replace its generated application entry with `mobile/native/ios/PocketMetrics.swift`. Run on the device. In Pocket Metrics, enable marks. In Shortcuts, create a personal automation for **App → Is Opened**, choose the apps yourself, and add **Mark a selected app opening**. Grant the automation its desired execution mode. Review the opening band and/or power and thermal state, export to Files, and import it in Pocket. Unmarked apps are unknown. No Screen Time entitlement is needed for this approach. Protected minute marks use a backup-excluded file; the collector prunes old marks on access, caps at 64 and attempts to erase them on disable. Locked files and missed automations reduce coverage. Only counts above zero generate a Shortcut receipt. This is an iOS app source entry point. Neither native collector was built or run on physical hardware during this edition.

**Bins.** For switch/activation events and selected Shortcut openings, few means 0–2, some 3–8 and many 9+. Durations are under 5, 5–under 20, or 20+ observed minutes. Sound variation is a local eight-second percentile spread in relative dB, split at 6 and 16 dB. Screenshot detail is the mean horizontal RGB difference in a 32-pixel-wide reduced image, split at 9 and 27 intensity units. These labels carry no semantic interpretation of the screen or the speaker.

## Verify

~~~sh
pytest -q --ignore=tests/e2e
for f in tests/js/*.mjs; do node $f; done
bash scripts/e2e.sh
~~~

The HTTP integration test builds a disposable certificate and checks a hostname-verified TLS connection. It skips if OpenSSL is unavailable. The Node checks exercise the shipped sensor controller, the service worker and the field model with synthetic media and time.

`scripts/e2e.sh` runs the browser tests in `tests/e2e` (`npm ci` installs the dev-only axe-core on first use). They drive Chromium with a fake microphone and camera against an in-process bridge on a free port and temporary database: the prototype journey, field session and vault, evening review, offline cold open, phone and tablet layouts, axe-core accessibility (no serious or critical findings), keyboard focus, and device handoff. Playwright's bundled Chromium is used by default; set `NSF_CHROMIUM=/usr/bin/chromium` to use a system browser. Screenshots of both layouts are written to `test-results/`. Native iPhone/Android capture, hardware power usage and real-world masking have not been validated.
